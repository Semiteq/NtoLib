# Индекс namespace в OPC UA: позиция, а не идентичность

Класс ошибок: сохранённый `NodeId` вида `ns=N;i=X` действителен только до тех пор, пока
таблица namespace сервера не изменится. Изменение таблицы не сопровождается ни ошибкой, ни
исключением.

## Симптом

Два варианта отказа.

**Значение не приходит.** Клиент подписывается на несуществующий узел, сервер возвращает
`BadNodeIdUnknown` в статусе по этому элементу, уведомления не поступают. В дереве
MasterSCADA тег отображается серым, поскольку качество пина остаётся не-Good. Записей об
ошибке нет ни в одном журнале.

**Приходят значения из другого namespace.** Если под устаревшим индексом расположен другой
namespace, в котором тот же идентификатор существует, клиент получает достоверные по форме
данные чужого интерфейса. Отличий от нормальной работы нет.

## Инцидент

В программу ПЛК добавили Server Interface `MBE2`. Он занял индекс 4 и сместил
`http://MBE` на индекс 5:

```
на момент захвата снимка (5 записей)   после добавления интерфейса (6 записей)
[4] http://MBE                         [4] http://MBE2
                                       [5] http://MBE
```

В снимке `OpcTreeManager` 1158 узлов из 1228 содержали `ns=4` и один узел верхнего уровня
(`CBr4`, 70 элементов, захваченный после смещения) содержал `ns=5`. После восстановления
работал только `CBr4`.

Идентификаторы `i=` смещение не затронуло. Доказательство: разность снимков, снятых до и
после ручного повторного обхода сервера через диалог настроек, дала для всех 17 элементов
`Cameras.Camera1` переход `ns=4;i=<X>` → `ns=5;i=<X>` при неизменном `<X>`.

## Почему это не чинится на нашей стороне

Индекс присваивает сервер в момент создания namespace во время работы. Из документации
Siemens:

> The server assigns a namespace index to each namespace when the namespace is created
> at runtime

В проекте TIA индекс не хранится и не настраивается: у Server Interface редактируется
только URI. Правило упорядочивания нескольких Server Interface в массиве не установлено.
Единственное наблюдение: `MBE` был создан раньше, `MBE2` позже, младший индекс получил
`MBE2`. Это исключает порядок создания и алфавитный порядок по возрастанию.

## Воркэраунд

Организационный, программного нет: фиксировать состав Server Interface на введённых в
эксплуатацию машинах и перечитывать `NamespaceArray` после каждой загрузки программы ПЛК.
Снимок, снятый до изменения таблицы, пересоздаётся под ту таблицу, на которой будет
применён.

Диагностика на объекте:

- Текущая таблица: узел `NamespaceArray` = `ns=0;i=2255`, доступен любому клиенту OPC UA.
- Состав интерфейсов и их URI: TIA Portal, `ПЛК → OPC UA communication → Server interfaces`.
- Инструмент SiOME позволяет изменять последовательность namespace в модели.

`OpcScadaItemDto.NodeId` хранит индексную форму, преобразований `ExpandedNodeId` в коде нет.
Переход на хранение URI (`nsu=<uri>;i=X`) не спроектирован: судьба уже развёрнутых файлов
`tree.json` не определена.
