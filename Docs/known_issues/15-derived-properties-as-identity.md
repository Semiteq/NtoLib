# Производные и защищённые свойства модели вендора как признак идентичности

Класс ошибок: вычисляемое свойство используется как признак типа, а свойство с закрытым
сеттером остаётся незаполненным при построении объекта через инициализатор. В обоих случаях
объект внешне корректен, а поведение отличается от ожидаемого.

## Симптом

- Поиск узла завершается сообщением `OPC group 'MBE' not found in ScadaRootNode` при том,
  что узел присутствует в дереве.
- Восстановленные узлы не архивируются, при том что настройки архивирования не менялись.

## Механизм

### Вычисляемое свойство `IsGroup`

Свойство определено как наличие потомков:

```csharp
public bool IsGroup => Items != null && Items.Count > 0;
```

Это признак текущего состава, а не типа узла. Отбор группы по одному этому свойству:

```csharp
if (child.IsGroup && string.Equals(child.Name, groupName, StringComparison.Ordinal))
```

теряет группу, из которой удалили всех потомков: узел в дереве есть, условию он не
удовлетворяет. Последовательность действий «удалить всё содержимое, затем восстановить» при
таком предикате невыполнима.

Пустая папка в проекте появляется не от того прохода, который её опустошил.
`OpcUaProtocol.DeleteFromProjectRec` удаляет опустевшую папку при `!IsNode` независимо от её
собственной галки; ветка, читающая галку, работает только для папки, пустой уже до прохода.
Папку, которую оператор видит пустой, создал следующий Apply.

**Статус реализации: предикат отбора — `!child.IsNode || child.IsGroup`.** Условие принимает
всё, кроме пустого листового пина. Папка (`IsNode == false`) находится при любом составе, а
`IsGroup` оставлен вторым слагаемым ради формы «переменная как группа» (`IsNode == true` с
потомками). Набор принимаемых узлов — надмножество прежнего: каждый узел, проходивший старое
условие, проходит и новое. Вне досягаемости остаётся пустой узел с `IsNode == true`, который
`FromSerializedToScadaTree` разворачивает в пару пинов `MBE` / `MBE$`; контейнером он быть не
может.

### Свойство с закрытым сеттером `IsHistorySupport`

`OpcUaScadaItem.IsHistorySupport` имеет закрытый сеттер и заполняется только конструктором
с девятью аргументами. Вендор вычисляет значение как
`(node.AccessLevel & PinType.HistoryRead) != 0`.

`OpcScadaItemDto` строит `OpcUaScadaItem` через инициализатор объекта и конструктор без
параметров, поэтому значение остаётся ложным у всех восстановленных узлов. Архивирование по
ним не ведётся, сообщений об этом нет.

Восстановить значение из существующих снимков невозможно: снимок хранит уже
замаскированный `PinValueType`, тогда как исходный признак выводится из `AccessLevel`.
Требуется расширение формата снимка.

**Статус реализации: свойство не захватывается и не восстанавливается.**

## Правило

1. Не использовать вычисляемое свойство как единственный предикат идентичности. Узел
   определяется типом (`IsNode`), именем и положением в дереве. `IsGroup` остаётся в поиске
   группы одним слагаемым и только ради формы «переменная как группа»: у неё `IsNode == true`,
   по типу она неотличима от листового пина, и прежний предикат её принимал. На папку это
   слагаемое не влияет — она находится и пустой.
2. Строить объекты вендора конструктором, заполняющим все поля. Инициализатор объекта
   оставляет свойства с закрытым сеттером в значении по умолчанию без каких-либо признаков.
3. При проектировании формата снимка сохранять исходные значения, а не производные от них:
   из маскированного значения исходное не восстанавливается.
